# Generic Payment Link UI

واجهة دفع مستقلة قابلة لإعادة الاستخدام، بتصميم يحاكي نمط صفحات الدفع المستضافة الشائعة، مع استلهام بصري من تجربة Stripe Payment Links. هذا المشروع غير تابع إلى Stripe ولا يستخدم شعاراتها أو علاماتها التجارية.

## الخصائص
- واجهة عربية RTL ومتجاوبة مع الهاتف والحاسوب.
- إدخال مبلغ مفتوح واختيار العملة (SAR أو USD).
- ملخص دفع يتحدث تلقائياً.
- اسم التاجر ووصف الدفع قابلان للتخصيص من ملف app.js.
- تحويل العميل إلى رابط الدفع المستضاف الذي يرجعه الخادم.

## الملفات
- index.html — بنية الصفحة.
- styles.css — التصميم والتجاوب.
- app.js — التحقق من المبلغ وتجهيز طلب الدفع.

## التشغيل محلياً
شغّل:
    python -m http.server 5500
ثم افتح http://localhost:5500.

## إعداد هوية التاجر
عدّل merchantName و paymentTitle و paymentDescription داخل الكائن CONFIG في app.js.

## ربط مزود الدفع
الواجهة غير متصلة حالياً بمزود دفع. أنشئ Backend endpoint:
POST /api/create-payment-session

مثال للطلب:
    { "amount": 120.00, "currency": "SAR" }

ينبغي أن يتحقق الخادم من المبلغ والعملة، وينشئ جلسة دفع لدى مزود الخدمة، ثم يعيد:
    { "checkoutUrl": "https://provider.example/checkout/..." }

بعد تنفيذ واختبار التكامل، غيّر apiConnected إلى true في app.js.

## الأمان
- لا تضع مفاتيح API السرية في ملفات المتصفح.
- لا تجمع بيانات البطاقات أو رموز التحقق في هذه الواجهة.
- استخدم صفحة الدفع المستضافة من مزود الدفع.
- يجب أن يتحقق الخادم من المبلغ والعملة ولا يعتمد على بيانات المتصفح وحدها.

## حدود المحاكاة
التصميم يحاكي تجربة صفحة الدفع بصرياً، لكنه ليس نسخة رسمية من Stripe، ولا يضمن تطابقاً بكسلياً مع كل إصدار أو إعداد إقليمي من صفحات Stripe؛ إذ قد تختلف صفحة الدفع الأصلية بحسب التاجر والبلد ووسائل الدفع المفعّلة.
